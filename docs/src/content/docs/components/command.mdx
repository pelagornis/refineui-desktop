## Usage

- `Command` is an entity (web `Command` + `CommandInput` + `CommandList` + `CommandEmpty`); subscribe to `CommandEvent::{Select, QueryChange, Highlight}` or give items `on_select`. A desktop command palette (⇧⌘P / Ctrl+Shift+P) is this component in a `CommandDialog`; there is no separate palette widget.
- Filtering is fuzzy (subsequence with word-start and contiguity bonuses) over the label, then value and keywords; matched letters are highlighted. Items sort by score within a group and groups by their best item. `should_filter(false)` turns it off; `filter(fn)` supplies your own scorer (web `filter`).
- When nothing matches, a compact `ResultView` (`ResultVariant::Empty`) is rendered inside the results plate, like web `CommandEmpty`. The search field is a sibling above that plate, so it stays pinned while the list scrolls.
- ↑ / ↓ move the indicator, Enter selects. `size` (default `md`) sizes the search field, rows, icons and the list radius together; the list grows up to `min(60% of the window, 320px)`, then scrolls. `hints(true)` adds an optional ↑↓ / ↵ / esc footer (desktop addition, off by default; the web has none).
- Desktop addition: `CommandItem::action("editor::Save")` dispatches that GPUI action when the item runs, and the row shows the shortcut bound to it in the installed keymap (unless `shortcut` is set).
- `CommandDialog` is the web `CommandDialog`, and like the web it is only a composition: a `Dialog` (`size`, default `Large`) with a transparent, unpadded panel (web `DialogContent` with `commandStyles.dialogContentPanel`, `scrollable={false}`) around the `Command`, which renders at `lg` unless it has an explicit `size` (web `commandProps.size ?? "lg"`). It looks exactly like an inline `Command`; the only dialog chrome is the scrim (`surfaceOverlay` plus the web 2px `overlayScrim` backdrop blur when materials are active). Everything else is the Dialog's own behaviour: Escape / outside click call `on_close`, opening focuses the search field (`Dialog::initial_focus`, web: first focusable) and clears the query (`Dialog::on_open`, web: the closed dialog unmounts its Command), closing returns focus. You could write the same thing by hand with `Dialog::new(..).bare(true).initial_focus(..).child(command)`; `CommandDialog` exists because the web exports it. Close it on `CommandEvent::Select` for palette-style use.
- **Breaking change (0.x)** — `Command::set_material` is removed: the results panel is always the web's opaque `backgroundPrimary` plate and the search field the filled SearchField, inline and in a `CommandDialog`.

```rust
use refineui::prelude::*;

let command = cx.new(|cx| Command::new(window, cx)
    .group(CommandGroup::new("Suggestions")
        .item(CommandItem::new("Calendar").icon(IconName::Calendar))
        .item(CommandItem::new("Search files").shortcut("⌘P"))));
cx.subscribe(&command, |this, _, event: &CommandEvent, cx| {
    if let CommandEvent::Select(value) = event {
        this.run(value, cx);
    }
})
.detach();

// ⌘K dialog:
CommandDialog::new("cmdk", self.command.clone())
    .open(self.open)
    .on_close(move |_window, cx| view.update(cx, |this, cx| {
        this.open = false;
        cx.notify();
    }));
```

Open the live, interactive version in the gallery:

```sh
cargo run -p refineui-gallery -- --story command
```

## Motion

A `surfaceHover` indicator slides between items over `duration-medium` (emphasized); rows press to 0.96; the empty `ResultView` fades in inside the results plate.

| Method | Description |
| --- | --- |

### CommandEvent

Emitted by `Command`.

| Variant | Description |
| --- | --- |
| `Select(SharedString)` | An item was run (Enter or click); carries its value. |
| `QueryChange(SharedString)` | The search query changed (web `onValueChange`). |
| `Highlight(SharedString)` | The highlighted item changed (web `onSelectedValueChange`). |

### CommandMatch

A scored match: higher is better; `positions` are matched label char indices.

### CommandDialog

Web `CommandDialog`: a `Command` inside a `crate::Dialog` whose panel is transparent (the search field and results panel float on the scrim). The command looks exactly like an inline one (same opaque results panel, search field, rows and tokens), at `lg` unless `Command::size` was set. The only dialog chrome is the modal scrim: `surfaceOverlay` with the web's 2px `overlayScrim` backdrop blur when materials are active.  It is only a composition, like the web: `crate::Dialog` (`bare`, `size` default `Large`) around the command. Controlled like `Dialog`: keep rendering it and pass `open`; close it in `on_close` (scrim click or Escape). The Dialog focuses the search field on open (web: first focusable in the panel) and gives focus back on close; each opening starts with an empty query (the web unmounts the closed dialog's Command). Items with `CommandItem::action` dispatch their action; close the dialog on `CommandEvent::Select` for ⇧⌘P-style use.

| Method | Description |
| --- | --- |
| `fn new(id: impl Into<ElementId>, command: Entity<Command>) -> Self` | Dialog around `command`. |
| `fn open(mut self, open: bool) -> Self` | Open state (web `open`). |
| `fn size(mut self, size: crate::DialogSize) -> Self` | Dialog width (web `size`). |
| `fn on_close(mut self, f: impl Fn(&mut Window, &mut App) + 'static) -> Self` | Close request (web `onOpenChange(false)`). |
| `fn inline(mut self, inline: bool) -> Self` | Render in flow (docs / previews). |

### Functions

| Function | Description |
| --- | --- |
| `fn fuzzy_match(query: &str, text: &str) -> Option<CommandMatch>` | Fuzzy subsequence match of `query` in `text` (case-insensitive).  Every query char must appear in order. Scores reward word-start hits, consecutive runs and an early first hit; returns `None` on no match. |

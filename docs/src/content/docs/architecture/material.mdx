The Material Engine (`crates/refineui-material`) gives surfaces a real
backdrop blur with tint, saturation, lighting, grain and elevation. The
**Materials**, **Material Effects**, **Material Recipes** and **Material
Components** pages under Foundations show it running; this page explains how
it is built.

## Why GPUI needs a patch

The findings below come from the gpui 0.2.2 source code, not its documentation.

- **Scene model** (`src/scene.rs`): elements push primitives (`Shadow`, `Quad`,
  `Path`, `Underline`, `MonochromeSprite`, `PolychromeSprite`, `Surface`) into
  per-kind vectors. Draw order comes from a `BoundsTree`: a primitive gets
  `1 + max(order of earlier overlapping primitives)`; `finish()` sorts each
  kind and `BatchIterator` merges kinds by `(order, kind)`. Layers
  (`paint_layer`) are only used for text lines.
- **Public paint API** (`Window::paint_*`): quads (with linear gradients),
  shadows (analytic Gaussian rounded rects), paths, sprites/images, SVGs,
  and `paint_surface` (macOS CVPixelBuffer only). There is **no** way to read
  back pixels drawn earlier in the frame, render to an offscreen target,
  supply a shader, or schedule an extra pass. → backdrop blur cannot be done
  through the public API.
- **Blade renderer** (`platform/blade/blade_renderer.rs`): one `main` render
  pass on the swapchain texture (surface usage `TARGET` only, format
  `Bgra8Unorm`, i.e. gamma-space values). It already *ends* the main pass for
  path batches, rasterizes into an intermediate texture
  (`COPY|RESOURCE|TARGET`) and *resumes* with `InitOp::Load` — the exact
  mid-frame pattern a backdrop blur needs. Blade inserts a barrier at every
  pass begin; texture-to-texture copies are available on Vulkan and Metal;
  Metal honours `framebufferOnly = false` when the usage is not `TARGET`.
- **Metal renderer** (`platform/mac/metal_renderer.rs`): one render command
  encoder per frame on the `CAMetalLayer` drawable (`BGRA8Unorm`), also ending
  and re-creating the encoder around path batches.
- **DirectX renderer**: the same batch loop; no intermediate-pass helper.
- **Clipping**: content masks are axis-aligned rects applied in shaders;
  rounded clipping exists only per primitive (quad SDF).


## Backdrop blur primitive

The smallest correct extension is a new scene primitive, kept in the vendored
gpui (`vendor/gpui`, `REFINEUI_PATCH.md`, `refineui.patch`) and applied with
`[patch.crates-io]`, so the graph has a single gpui 0.2.2:

1. `BackdropBlur { bounds, content_mask, corner_radii, sigma, tint,
   saturation, opacity }`, ordered by its *sampled* region (shape + 3σ) so
   everything under the kernel footprint is drawn first; it sorts first among
   kinds of the same order so a surface's own fill/text draw above it.
2. Renderer: close the main pass → copy the sampled region of the drawable →
   box-downsample (1/2/4/8 by σ) into `Rgba16Float` → separable Gaussian
   (H, V) → composite with saturation, tint, rounded-rect SDF, opacity →
   resume the main pass. Textures are cached per drawable size.
3. `Window::paint_backdrop_blur` + `backdrop_blur_supported()` (false on
   Windows, which paints the documented fallback instead).


Alternatives that were not used:
- translucent fills, because they are not a blur;
- a second OS window behind the content, because it cannot blur in-window content;
- rendering every frame offscreen, which adds a full-screen copy per window even when nothing is blurred;
- a git fork of gpui, which would put a second gpui in the dependency graph.

## Crates

```
crates/
  refineui-foundation   tokens (GPUI-free, no deps) + material tokens + contracts
  refineui-tokens       compatibility re-export of refineui-foundation
  refineui-material     Material Engine (gpui + foundation only)
  refineui              components, shell, workspace (`material` feature)
examples/gallery        showcase + screenshot generator
vendor/gpui             gpui 0.2.2 + BackdropBlur
```

Dependency rules: foundation → nothing; material → gpui + foundation (never
components); refineui → gpui + foundation, plus material behind its
`material` feature.

## Effects

Every effect runs inside the single blur **composite** pass (one draw over the
shape plus its shadow extent), so effects add no passes:

| Area | What | Where |
| --- | --- | --- |
| Glass | saturation, tint with a blend mode (`BlendMode`: normal, multiply, screen, overlay, soft light), grain, ±1 LSB dithering against banding | `composite.rs`, `backdrop_blur.wgsl` / `shaders.metal` |
| Lighting | directional sheen + far-side shade, ambient lift, edge rim along the rounded-rect normal (facing the light), diagonal reflection band, Gaussian specular spot | `lighting.rs` (`Lighting`) |
| Texture | integer-hash grain per device pixel (no texture fetch); fallback uses a cached grain tile | `texture.rs`, shaders |
| Shadows | up to 4 drop shadows (`ShadowPreset` incl. `Ambient`, elevation tokens) drawn by the composite **outside the shape only** with gpui's erf shadow model; `InnerShadow` presets (`pressed`, `well`, `glass_rim`) | `shadow.rs` |
| Compositing | premultiplied “over” of plate and shadow; linear `Mask`; rounded-rect clip; nested materials sample what the outer one composited | `composite.rs` (module docs list the rules) |
| Recipes | sidebar, titlebar, popover, menu, tooltip, HUD, sheet, toast, scrim, glass | `recipes.rs` (`Recipe`) |

Drop shadows are drawn by the composite outside the shape (like CSS
`box-shadow`), so a material never samples its own shadow; shadows beyond four
use GPUI shadows. A blur inside a `paint_layer` is ordered by the union of its
sampled region and the layer bounds, so labels and icons painted later in the
same layer stay above it.

### Fallback

Without real blur (DirectX on Windows, or
`MaterialSettings { reduced_transparency: true }`) a `Material` paints: GPUI
shadows → fallback fill (a gradient when masked) → grain tile → quad lighting
(directional / ambient / rim; specular approximated by a clipped white glow) →
inner shadows → border. The reflection band and blend modes are blur-only.

## Caching

`Scene::backdrop_blur_keys` hashes, per blur, every primitive drawn before it
whose bounds intersect its sampled region (plus the blur's own parameters and
any earlier blur it samples). When the key matches the previous frame the
renderer skips copy / downsample / Gaussian and only runs the composite inside
the main pass (no pass break). Misses copy the blurred result into a per-key
texture. Entries unused for 3 frames are evicted (max 24). Surfaces (video)
make a blur uncacheable. `GPUI_BLUR_CACHE=0` disables the cache.

## Components on materials

`refineui` has an optional **`material`** feature (off by default, so stock
gpui keeps working; the gallery turns it on). `refineui::material` holds the
glue: `SurfaceKind` (panel, sidebar, titlebar, popover, menu, tooltip, HUD,
sheet, toast, scrim, glass → recipe + opaque fallback) and
`materials_active(cx)` (feature on and `MaterialSettings::blur_enabled`).
Without the feature every component renders its opaque web-parity fill.

| Component | With materials | API |
| --- | --- | --- |
| Surface (new) | `div` with a material plate per `SurfaceKind` | `Surface::new(kind)`, `radius`, `elevation`, `border_color_override` |
| Text / Icon | colors that read on a surface (light on the HUD) | `Text::on_surface`, `Icon::on_surface` |
| Separator | alias of `Divider`; translucent rule on surfaces | `Separator`, `Divider::on_surface` |
| Button | glass plate + hover / press veil | `Button::glass(bool)` (opt-in) |
| Input | material field plate, animated border above the blur | `TextInput::glass(bool)`, `set_glass` (opt-in) |
| Popover, Tooltip | panel = Popover / Tooltip material; outline strokes the panel and fills only the beak | automatic |
| Menu (Dropdown, ContextMenu, submenus, Menu Bar) | Menu material | automatic |
| Dialog / Drawer | scrim = Scrim material (the web 2px blur); panel = Sheet material on request | automatic scrim, `Dialog::material(bool)` |
| Toast | Toast material | `Toast::material(bool)`, `Toaster::material(bool)` (opt-in) |

Where the web design is opaque (buttons, inputs, toasts, dialog panels) the
material is opt-in. `Select`'s list is a Menu material on a non-scrolling
outer plate with the scroll container inside; the Sidebar peek is a Popover
material; `DragPreview` chips are Menu material. A `Command` stays opaque
(web parity), also inside a `CommandDialog`, where only the scrim blurs.

### Shell and workspace chrome

A crate-internal `material::chrome(kind, fill, cx)` returns a transparent fill
plus a square, borderless, shadowless material layer, so the one-sided
hairlines the shell draws stay visible:

| Piece | Kind |
| --- | --- |
| Titlebar, Status Bar, Tab Bar strip | `Titlebar` |
| Activity Bar, Sidebar rail, Dock side docks, Application Shell menu strip and side docks | `Sidebar` |
| Notification Center | `Sheet` (rounded, rim, `Shadow16`) |
| Preferences sidebar | `Sidebar` |


The workspace (editor, panels, inspector content, bottom dock) stays on opaque
`backgroundPrimary`. Over an opaque window the chrome materials blur that
fill, so the look is unchanged. With `ApplicationShell::vibrant(true)` the
shell root is left unpainted and the chrome blurs what is behind the window (a
transparent or blurred OS window, or the gallery wallpaper). The Floating
Panel has its own OS-level blur (`FloatingPanelFrame::blurred`); its titlebar
is chrome.

## Benchmarks

`cargo run --release -p refineui-material --example blur_bench -- <panels>`
opens a 960×640 window with an animated busy backdrop and N `Regular` panels.
Measured on Xvfb + **lavapipe (software Vulkan on the CPU)** in release;
frames are paced by the 60 Hz timer, so results are quantized to ~16.7 ms:

16 `Regular` panels, 960×640, Xvfb + lavapipe, release. Frames are paced by
the 60 Hz refresh timer, so results are quantized to ~16.7 ms steps.

| Scenario | Cache on | Cache off (`GPUI_BLUR_CACHE=0`) |
| --- | --- | --- |
| `blur/moving` (panels move, every blur recomputed) | 31.8 ms | 32.0 ms |
| `blur/static` (only a small widget animates) | 16.0 ms (capped) | 31.9 ms |
| `fallback` (reduced transparency) | 16.0 ms (capped) | 16.5 ms |

The static case drops from re-blurring every panel to composite-only. With 8
panels every phase sits at the 60 Hz cap on this machine.

No hardware GPU numbers have been measured yet.

## Risks

- The vendored gpui must be re-patched on every gpui upgrade.
- The Metal path is not verified on hardware output: the Rust side builds on
  macOS and the MSL is syntax-checked, but blurred output has only been
  inspected on Blade.
- Blur cost scales with the sampled area; many large blurred surfaces on
  integrated GPUs rely on the cache.
- MSRV is 1.98 (required by the icons crate).

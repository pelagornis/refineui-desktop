RefineUI Desktop is a **desktop-native** design system for GPUI. It keeps the
RefineUI visual identity (see [Visual identity](/architecture/identity/)) and
adds what desktop applications need: keyboard-first interaction, resizable
multi-panel workspaces, an application shell and platform adapters. It is
**not** a port of the React components. Web-oriented patterns are optional.

## Layers

```text
 Platform      macOS · Windows · Linux adapters            refineui::platform
 Application   Window · Titlebar · Menu Bar · Toolbar ·    refineui::shell
               Activity Bar · Status Bar · Shell
 Composition   Split View · Panel Group · Dock Area ·      refineui::workspace
               Tab Group · Floating Panel · Inspector
 Components    Button · Input · Menu · Dialog · Table ·    refineui::components
               Tree · …
 Interaction   Focus · Keymap · Selection · Drag & Drop    refineui::interaction
 Foundation    Tokens · Theme · Density · Elevation ·      refineui_tokens (data)
               Motion · Blur · Layers · Cursor             refineui::foundation (GPUI)
```

A layer may use the layers **below** it, never above. Platform is the
exception: it is a set of adapters that any layer can query through a
trait (`PlatformAdapter`). OS code stays behind `cfg` inside the adapter.

## Crates and modules

| Crate / module | GPUI? | Contents |
| --- | --- | --- |
| `refineui-tokens` | **No** | Palette, semantic colors, typography, spacing, radius, stroke, opacity, elevation, motion, blur, z-index, sizes, **density** (`Density`, `DesktopMetrics`), **window metrics**, **component contracts** (`contracts/*.json` + schema) |
| `refineui::foundation` | Yes | `Theme`, density access, focus ring, `LayerOrder`, `CursorRole`, frost (`vibrancy`) |
| `refineui::interaction` | Logic only (GPUI-free state machines) | `keymap` (contexts, conflicts), `selection`, `focus` (roving), `dnd` (drop geometry) |
| `refineui::components` | Yes | The component set |
| `refineui::workspace` | Logic only (`serde` with the `serde` feature) | `layout`: the persisted workspace layout model |
| `refineui::shell` | Logic now; GPUI views in Phase 2 | Shell regions and chrome metrics per platform / density |
| `refineui::platform` | Logic + `cfg` glue | `PlatformAdapter`, `MacOsAdapter`, `WindowsAdapter`, `LinuxAdapter` |

We kept this to **two crates**. Separate crates for each layer would add
version and re-export overhead without stronger guarantees, since the
module boundaries are enforced by review and by the rules below (brief
principle 7). The only hard split is the one the brief requires: shared
contracts (`refineui-tokens`) never depend on GPUI.

`use refineui::prelude::*` re-exports components, the theme, density,
`LayerOrder`, `CursorRole`, `SelectionModel` and `PlatformAdapter`.

## Rules (brief §8)

1. GPUI-native primitives and lifecycle: `RenderOnce` for stateless
   pieces, entities for stateful views, element state for transient state.
2. No copied React APIs. Builder methods follow GPUI style.
3. Application state (layout, selection, documents) is plain data owned
   by the app. Transient state (hover, drag-in-flight, animations) lives in
   components.
4. Composable primitives over monoliths.
5. Keyboard and mouse for everything. Nothing is hover-only.
6. Virtualize large lists, tables and trees (`uniform_list` / `list`).
7. OS behaviour only through `platform`.
8. No literal colors or sizes where a semantic token exists.
9. Every public component has a machine-readable
   [contract](/architecture/contracts/); a test enforces it.

## Phase plan

| Phase | Brief §9 steps | Scope | Status |
| --- | --- | --- | --- |
| 1 | 1–5 | Inspect, inventory, contracts, layer architecture, shell design. Skeleton modules plus tests. `web-extras` split. | **Done** |
| 2 | 6 | Foundation and interaction in GPUI: density everywhere (Spacious), focus regions (F6), keymap → GPUI bindings and Shortcut Hint, drag handle / preview / drop zone, selection box, cursor roles; Command Palette; shell chrome (Window, Titlebar, Window Controls, Menu Bar, Toolbar, Status Bar, Activity Bar / Navigation Rail, Application Shell) | **Done** |

| 4 | 8 | Adapt reusable components to their contracts (all 8 states, density, keyboard). Virtualized Table and Tree with multi-select and DnD. Empty and Error State | |

| 6 | 10 | Public API docs and examples (IDE, creative app, AI app) | |

### Phase 3 plan (workspace composition)

1. **Split View + Resizable Handle** on `workspace::layout` splits: ratio and
   minimum sizes, collapse, keyboard resize, double-click reset, density hit
   areas (`splitter_hit`).
2. **Panel / Panel Group** — panel header (title, actions, overflow), tabs
   of panels inside a dock, collapse / expand, focus by shortcut.
3. **Dock / Dock Area** — `ShellDock` becomes resizable and persisted;
   left / right / bottom docks; drag a panel between docks with
   `DropZone`; zoom (maximize) a dock.
4. **Tab Bar / Tab Group / Document Tab** — reorder with
   `DropIndicator::between_tabs`, dirty / pinned / preview tabs, context
   menu (close others, split), overflow, drag a tab onto a pane edge to
   split (`dock_zone`) → layout mutations.
5. **Inspector** (property grid for the right dock) and **Floating Panel**
   (a detached GPUI window with frost).
6. **Persistence** — `workspace::layout` (serde) saved with `WindowState`;
   session restore per window; multiple windows.
7. Toolbar overflow menu; the shell demo grows split editors, draggable
   tabs and resizable docks.
8. Platform track alongside: Windows Mica / Acrylic in `platform::windows`.

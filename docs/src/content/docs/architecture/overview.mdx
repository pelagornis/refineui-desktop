RefineUI Desktop is a **desktop-native** design system for GPUI. It keeps the
RefineUI visual identity (see [Visual identity](/architecture/identity/)) and
adds what desktop applications need: keyboard-first interaction, resizable
multi-panel workspaces, an application shell and platform adapters. It is
**not** a port of the React components, and web-oriented patterns are optional.

## Layers

```text
 Platform      macOS · Windows · Linux adapters            refineui::platform
 Application   Window · Titlebar · Menu Bar · Toolbar ·    refineui::shell
               Activity Bar · Status Bar · Shell
 Composition   Split View · Panel Group · Dock Area ·      refineui::workspace
               Tab Group · Floating Panel · Inspector
 Components    Button · Input · Menu · Dialog · Table ·    refineui::components
               Tree · …
 Interaction   Focus · Keymap · Selection · Drag & Drop    refineui::interaction
 Foundation    Tokens · Theme · Density · Elevation ·      refineui-foundation (data)
               Motion · Blur · Layers · Cursor             refineui::foundation (GPUI)
```

A layer may use the layers **below** it, never above. Platform is the
exception: it is a set of adapters that any layer can query through a
trait (`PlatformAdapter`). OS code stays behind `cfg` inside the adapter.

## Crates and modules

| Crate / module | GPUI? | Contents |
| --- | --- | --- |
| `refineui-foundation` | **No** | Palette, semantic colors, typography, spacing, radius, stroke, opacity, elevation, motion, blur, **material roles** (`MaterialRole`, `MaterialTokens`), z-index, sizes, **density** (`Density`, `DesktopMetrics`), **window metrics**, **component contracts** (`contracts/*.json` + schema) |
| `refineui-tokens` | **No** | Compatibility re-export of `refineui-foundation` |
| `refineui-material` | Yes (gpui + foundation only) | Material Engine: `Material`, real backdrop blur, saturation, tint, lighting, grain, elevation shadows, `MaterialSurface`, recipes — see [Material Engine](/architecture/material/) |
| `vendor/gpui` | — | gpui 0.2.2 + the `BackdropBlur` primitive, applied with `[patch.crates-io]` |
| `refineui::foundation` | Yes | Theme and density access, `LayerOrder`, `CursorRole`, re-exported blur / window / z-index tokens |
| `refineui::interaction` | State machines (GPUI-free) | `keymap` (contexts, conflicts, `KeybindingManager`), `selection` (`SelectionModel`), `focus` (roving focus, regions), `dnd` (drop geometry) |
| `refineui::components` | Yes | The component set (re-exported at the crate root) |
| `refineui::shell` | Yes | Window presets and state, Titlebar, Window Controls, Window Frame, Menu Bar, Activity Bar, Status Bar, Application Shell, Floating Panel, Notification Center, Preferences Window, session restore |
| `refineui::workspace` | Yes (`layout` is plain data) | Split View, Panel, Panel Group, Dock, Dock Area, Tab Bar, Tab Group, Inspector; `layout` is the persisted workspace model (`serde` feature) |
| `refineui::platform` | Logic + `cfg` glue | `PlatformAdapter`, `MacOsAdapter`, `WindowsAdapter`, `LinuxAdapter`, `Os`, `ScrollbarStyle`; `platform::windows` backdrop types |
| `refineui::material` | Yes | `SurfaceKind`, `materials_active` — the glue between components and the Material Engine |
| `refineui::motion` | Yes | Tweens, springs and `ReducedMotion` |

Crates follow three layers: **Foundation** (`refineui-foundation`,
GPUI-free), **Desktop** (`refineui`: components, interaction, workspace,
shell, platform) and **Material** (`refineui-material`). Material depends only
on GPUI and the foundation, never on components; `refineui` uses it behind the
`material` feature. Inside `refineui` the sub-layers stay modules, because
separate crates would add version and re-export overhead without stronger
guarantees. Shared contracts never depend on GPUI.

`use refineui::prelude::*` re-exports the components, the theme, density,
`LayerOrder`, `CursorRole`, `KeybindingManager`, `SelectionModel`, motion,
`PlatformAdapter`, and the shell and workspace types.
`refineui::init(cx)` registers the bundled fonts, the theme global and the
default key bindings.

## Cargo features

| Feature | Default | Effect |
| --- | --- | --- |
| `bundled-fonts` | yes | Embed Inter. |
| `syntax-highlight` | yes | CodeBlock colours (syntect). |
| `web-extras` | no | The web page `container()` / `container_with()` (outside Desktop Core). |
| `serde` | no | `Serialize` / `Deserialize` for `workspace::layout`. |
| `material` | no | Components on the Material Engine (real backdrop blur for Popover, Tooltip, Menu, the dialog scrim, `Surface`, opt-in glass Button / Input / Toast / Dialog). Needs the vendored gpui patch (see Installation). |

## Rules

1. GPUI-native primitives and lifecycle: `RenderOnce` for stateless
   pieces, entities for stateful views, element state for transient state.
2. No copied React APIs. Builder methods follow GPUI style.
3. Application state (layout, selection, documents) is plain data owned
   by the app. Transient state (hover, drag-in-flight, animations) lives in
   components.
4. Composable primitives over monoliths.
5. Keyboard and mouse for everything. Nothing is hover-only.
6. Virtualize large lists, tables and trees (`uniform_list` / `list`).
7. OS behaviour only through `platform`.
8. No literal colors or sizes where a semantic token exists.
9. Every public component has a machine-readable
   [contract](/architecture/contracts/); a test enforces it.

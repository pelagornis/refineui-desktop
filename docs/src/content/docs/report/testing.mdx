## Visual regression

`examples/gallery/tests/visual_regression.rs` renders a set of stories in
light and dark with the `refineui-screenshots` binary:

- button
- select
- material-recipes
- material-components
- application-shell
- notification-center
- result
- desktop-showcase

It compares each PNG with `tests/visual/baselines/<os>/`:

- A pixel differs when any RGBA channel differs by more than
  `REFINEUI_VISUAL_THRESHOLD` (default 24/255). This absorbs GPU and font
  anti-aliasing noise.
- A story fails when more than `REFINEUI_VISUAL_TOLERANCE` (default 0.5%)
  of its pixels differ, or when its size changed.
- Failures write the actual image and a red-on-grey diff to
  `target/visual-regression/`.

```sh
./scripts/visual-regression.sh            # compare
./scripts/visual-regression.sh --update   # write this OS's baselines
./scripts/visual-regression.sh --strict   # fail instead of skipping
./scripts/visual-regression.sh --only select,result
```

Baselines are per OS because font rasterization and GPU differ between
platforms. Linux baselines are committed (rendered at 2× on Xvfb and
lavapipe). Create the macOS ones on the Mac with `--update`.

The test **skips** with a note on stderr, and passes, when it cannot render:

- `REFINEUI_VISUAL=0` is set.
- Linux with no `$DISPLAY`.
- No baselines exist for this OS.
- The renderer fails: no GPU, no display, or no Screen Recording permission
  on macOS.
- The renderer times out.

With `--strict` (`REFINEUI_VISUAL_STRICT=1`), these skips fail instead; use
this on CI machines that have a display. The latest Linux run: all 16
images within 0.005% (the button's focus-ring edge); every other image was
identical.
